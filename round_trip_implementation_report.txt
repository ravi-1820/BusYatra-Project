BUSYATRA - ROUND TRIP BOOKING SYSTEM IMPLEMENTATION REPORT
===============================================================================

1. SYSTEM ARCHITECTURE & FLOW ANALYSIS
-------------------------------------------------------------------------------
The Round Trip Booking System has been engineered for BusYatra as a seamlessly
integrated single-flow booking journey. Customers can select a return trip when
searching for buses, choose both departure and return buses, pick independent
seats for both legs, fill a single passenger form, make a single Razorpay payment,
and receive a single unified E-Ticket PDF with combined email confirmation.

Backend database integrity is maintained by storing two separate `Booking` model
records per passenger (one for Departure journey, one for Return journey), linked
together via a shared `round_trip_id` UUID field and designated with `journey_type='ROUND_TRIP'`.

2. MODEL & DATABASE SCHEMA CHANGES
-------------------------------------------------------------------------------
File: Bus/models.py
Migration File: Bus/migrations/0013_booking_journey_type_booking_round_trip_id_and_more.py

Fields added to `Booking` model:
- `journey_type`: CharField(max_length=20, choices=[('ONE_WAY', 'One Way'), ('ROUND_TRIP', 'Round Trip')], default='ONE_WAY', db_index=True)
- `round_trip_id`: UUIDField(default=None, null=True, blank=True, db_index=True)

3. SEARCH INTERFACE & VALIDATION
-------------------------------------------------------------------------------
File: Bus/templates/index.html & Bus/views.py (`get_search_details`)
- Integrated Return Date datepicker container (`id="returnDateCol"`).
- Dynamic radio toggle ("One Way" vs "Round Trip") automatically shows/hides return date field.
- Auto-constrained Return Date minimum selectable date to Travel Date (`min=travel_date`).
- Server-side and Client-side validation enforcing `return_date >= travel_date`.

4. DUAL BUS LISTING & SELECTION
-------------------------------------------------------------------------------
File: Bus/templates/bus_list.html & Bus/views.py (`bus_list`)
- When `round_trip=1` is active, two independent querysets (`dep_buses` and `ret_buses`) are evaluated.
- Live seat availability calculation (`set_live_available_seats`) is applied to both querysets for their respective travel dates.
- Interactive dual cards allow selecting 1 Departure Bus and 1 Return Bus.
- Sticky action bar enables "Proceed to Seat Selection" button only after both departure and return buses are selected.

5. SEAT SELECTION & PASSENGER DATA FLOW
-------------------------------------------------------------------------------
File: Bus/templates/seat_booking.html & Bus/views.py (`seat_booking`)
- Dual interactive seat grids are presented:
  1. Departure Bus Seat Layout
  2. Return Bus Seat Layout
- Passenger information form (Passenger 1..N) is filled ONCE and applied to both legs.
- Server-side double booking verification ensures seats in both journeys are still free prior to pending booking creation.
- DB creation is wrapped inside `django.db.transaction.atomic()` to guarantee atomic record generation.

6. COMBINED PAYMENT & RAZORPAY INTEGRATION
-------------------------------------------------------------------------------
File: Bus/templates/payment.html & Bus/views.py (`payment`)
- Displays itemized pricing for both Departure and Return legs.
- Grand Total calculation:
  Subtotal = (Departure Fares + Return Fares)
  GST (5%) = (Subtotal * 0.05)
  Convenience Fee = (40 * Passengers Count)
  Grand Total = Subtotal + GST + Convenience Fee
- Single Razorpay payment order created server-side for Grand Total.

7. E-TICKET PDF & CONFIRMATION EMAIL SYSTEM
-------------------------------------------------------------------------------
File: Bus/views.py (`ticket`, `download_ticket_pdf`, `generate_ticket_pdf_bytes`)
- Generates a combined PDF E-Ticket detailing:
  - Header with Company Branding & Booking Date
  - Departure Journey Section (Route, Bus Name, Date, Departure/Arrival Times, QR Code)
  - Return Journey Section (Route, Bus Name, Date, Departure/Arrival Times, QR Code)
  - Transaction Details (Payment ID, Payment Status, Grand Total)
  - Passenger & Seat Details Grid (All passengers & assigned seats across journeys)
  - Terms & Guidelines
- Sends ONE confirmation email with PDF attached (`BusYatra_Ticket.pdf`).

8. BOOKING HISTORY GROUPING
-------------------------------------------------------------------------------
File: Bus/templates/my-orders.html & Bus/views.py (`build_order_groups`)
- Groups records matching `round_trip_id` into a single order card.
- Card displays "Round Trip" badge, Route (`Source ⇄ Destination`), Departure & Return trip summaries.
- Single click action buttons: "View E-Ticket" and "Download PDF".

9. REGRESSION SAFETY & BACKWARD COMPATIBILITY

- Manager and Admin dashboards, bus CRUD, schedule CRUD, route management, and user authentication remain untouched.
